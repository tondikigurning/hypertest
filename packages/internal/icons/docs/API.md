# @hyperscal/icons — API Reference

> The public contract between this package and its consumers.
> **Only what is exported from an entry point belongs here.**

**Status:** draft · **Package:** `packages/internal/icons` · **Updated:** 2026-07-02

## Entry points

| Import path                     | Source                                  | Contents                                                                                                                                                                                                              |
| ------------------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@hyperscal/icons`              | `src/index.ts`                          | The `Icon` component + the `IconName` type. What ~523 consumers use.                                                                                                                                                  |
| `@hyperscal/icons/icons`        | `src/gen/types.ts` (generated)          | Just the `IconName` type and the `icons` array of valid names — no React import. Used where you need the name list/type without pulling in the component (e.g. populating a `ComboBox` of icon choices in Storybook). |
| `@hyperscal/icons/icon.css`     | `dist/icon.css` (generated, built only) | The generated stylesheet — every consuming app imports this once, globally. **Not resolvable from source in dev**; see Notes below and [[icons-guide]].                                                               |
| `@hyperscal/icons/package.json` | The package manifest itself             | Standard `exports["./package.json"]` convention.                                                                                                                                                                      |

**Generated surface note:** `src/gen/icon.css` and `src/gen/types.ts` are
git-ignored, regenerated by `pnpm run gen` from `icon.mjs` (the curated
opt-in icon list) + `@iconify-json/tabler`'s data. Treat them as opaque
output — don't hand-edit, don't bulk-read `icon.css` (1000+ lines of
generated CSS). The generated surface is documented here as a _pattern_
(one `.i-{name}` class + one `IconName` union member per opted-in icon),
not as an enumerated symbol list — see [[icons-guide]] for how to add a new
icon.

## Components

### `Icon`

Renders an icon as a CSS-class-driven element (`<i class="i-{name}">` by
default).

```tsx
import { Icon } from "@hyperscal/icons";

<Icon name="user" />
<Icon as="span" name="settings" enlarged aria-label="Settings" />
```

**Props (`IconProps<T>`):**
| Prop | Type | Required | Default | Description |
|---|---|---|---|---|
| `name` | `IconName` (generated union of curated icon names) | yes | — | Which icon to render — only opted-in names typecheck. |
| `as` | `T extends React.ElementType` | no | `"i"` | The element/component to render as. |
| `enlarged` | `boolean` | no | `false` | Adds a `text-[1.6em]` class for a larger rendering. |
| `className` | `string` | no | — | Merged with the generated `i-{name}` class (and `text-[1.6em]` if `enlarged`). |
| `customIcons` | — | no | — | Accepted and discarded — **has no effect** (see Notes). |
| `...rest` | `Omit<React.ComponentPropsWithoutRef<T>, "as" \| "name">` | no | — | Any other prop valid on the underlying element (`aria-label`, `onClick`, `style`, etc.). |

**Notes:**

- **⚠️ `enlarged` is not stripped from the prop spread** — the component
  reads `props.enlarged` for the className logic but doesn't destructure
  `enlarged` out before spreading `...props` onto the rendered element, so
  `enlarged` is passed through as a literal attribute too (e.g.
  `<i enlarged="true" class="i-user text-[1.6em]">`). Harmless visually,
  but not clean — don't rely on this; it may be fixed in a future patch
  (see [[icons-internals]]).
- **`customIcons` does nothing.** It's destructured out (so it won't leak
  to the DOM like `enlarged` does) but never read or used anywhere in the
  component. Passing it has zero effect either way. It's also not part of
  `IconProps`'s declared type, so TypeScript will reject it unless `as` is
  set to a component that happens to accept a `customIcons` prop of its
  own.
- The rendered class is always `i-{name}` — there's no prefix/namespace
  customization.

## Exported types

### `IconName`

```ts
type IconName = (typeof icons)[number]; // generated union, e.g. "user" | "settings" | "chevron-down" | ...
```

The full list of currently-opted-in icon names. Generated — grows/shrinks
only when `icon.mjs` is edited and `pnpm run gen` is re-run (see
[[icons-guide]]). Passing a name not in this union is a typecheck error,
not a runtime failure — there's no runtime validation of `name`.

## Versioning contract

Internal-only (`private: true`, `version: 0.0.0`, consumed via
`workspace:*`) — no semver releases. "Breaking" = breaking a consumer at
typecheck or runtime. ~523 importing files.

**Breaking:**

- Removing an icon from `icon.mjs` (and re-running `gen`) — every consumer
  passing that `name` breaks at typecheck (the union narrows) and the
  matching CSS class disappears (runtime: the icon silently renders
  nothing, since there's no fallback glyph).
- Renaming `Icon`, changing `name`'s required-ness, or changing the
  generated class naming scheme (`i-{name}`) — apps rely on this exact
  class name pattern in a few places (e.g. custom CSS targeting `.i-*`
  selectors).
- Changing the `./icon.css` export's resolution (dist-only) without
  updating both consuming apps' `vite.config.ts` aliases.

**Non-breaking:**

- Adding a new icon to `icon.mjs` and regenerating — purely additive to the
  `IconName` union and the CSS.
- Fixing the `enlarged` prop-leak or wiring up (or removing) `customIcons`
  — neither is part of any documented/relied-upon contract today.
