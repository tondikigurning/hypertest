## Current bugs

| ID    | File                                                                             | Problem                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BUG-1 | `src/control.css` (throughout: lines 7, 13, 23–24, 33, 39, 49–50, 59, 65, 75–76) | **High.** `var(--font-size-small/normal/large)` is referenced by every `control-*`, `button-*`, and `icon-*` class but **defined nowhere in the repo** (repo-wide grep: only the usage site). Consequence: `.icon-sm/md/lg` get `width/height: auto` (icons render at SVG intrinsic size), and `.control-*`/`.button-*` `font-size` falls back to inherit. **Live**: `wizard-step.variant.ts` maps its size variants to `button-*`/`icon-*` (used by order-management's new-order wizard), and `control-md` ships in `StatusIndicator`/`PriorityIndicator`/`TaggableInput`/`SubjectInput` (used in admin + CRM pages). Fix: define the three vars in `backoffice.css` `:root` (mapping onto the `--text-*` scale) or migrate the classes to `--text-*`. |
| BUG-2 | `src/control.css:70–72`                                                          | **Medium.** `.button-md.rounded-full` is defined **twice**; the second copy sits right after `.button-lg` and uses `--button-lg-spacing-relaxed` — a copy-paste of what should be `.button-lg.rounded-full`. Net effect: md round buttons get lg relaxed padding (later rule wins); lg round buttons get no relaxed padding at all. Dormant — no consumer currently combines these classes — but silently misbehaves on first use.                                                                                                                                                                                                                                                                                                                      |
| BUG-3 | `src/control.css:66`                                                             | **Medium.** `.button-lg` uses `--control-md-line-height` (1.5) instead of `--control-lg-line-height` (1.75). Every other size class follows the matching-suffix pattern; lg buttons render with md line density. Not documented as deliberate.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| BUG-4 | `backoffice.css:85, 130` (+ [[tailwind-config-intent]])                          | **Medium.** The neutral-palette `[ACTIVE]` labels lie: both the header comment and the block-3 label mark **Purple-tinted slate** as active, but that block is commented out — the live palette is block 2 (**Slate**, `neutral-500: #728093`, not `#7c7293`). INTENT.md's "Locked design decisions" repeats the wrong claim. Any token audit or palette extension built from the label produces wrong colors. Fix the labels AND the INTENT.md row (or re-activate purple-tinted if that was the real intent — owner ruling).                                                                                                                                                                                                                          |
| BUG-5 | `backoffice.css:324`                                                             | **Medium.** `body { width: 100vw }` — on platforms with classic (non-overlay) scrollbars, 100vw includes the vertical-scrollbar width, so the body overflows horizontally by ~15px and every page grows a horizontal scrollbar. The old mitigation is right there, commented out (`/* overflow: hidden; */`, line 327), and neither tenants' nor admin's root adds a compensating rule. Fix: `width: 100%` (or restore an overflow rule deliberately).                                                                                                                                                                                                                                                                                                  |
| BUG-6 | `src/control.css` (missing rule)                                                 | **Low.** `@hyperscal/ui`'s `legacy-icons` cva maps `size="extra-small"` → `icon-xs`, but no `.icon-xs` rule exists here (the scale defines `h-xs`/`input-h-xs` but skips `icon-xs`). Dormant — `LegacyIcon` currently has zero app usage — but bites whoever first uses the extra-small variant.                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

## Build & bundle inefficiencies

| ID     | File                            | Problem                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------ | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PERF-1 | `backoffice.css:8–15` (@source) | **Medium.** `@hyperscal/services` and `@hyperscal/file-uploader` ship React components with real Tailwind classes but have **no `@source` entry** — and apps consume them via `dist/` (`main: ./dist/index.mjs`), which Tailwind never scans. Verified 2026-07-03: of 87 class tokens in their `src/`, every real one is currently _rescued_ by overlap with scanned sources (the only unique token, `align-end`, isn't a real Tailwind utility) — so nothing is broken **today**, but the first class used only in these packages silently renders unstyled in prod with no build error. Precedent for the fix: `ui`, `icons`, `form` already have explicit entries. Add `@source` lines for both. |
| PERF-2 | `backoffice.css:18`             | **Low.** `@source inline("row-start-{1..100}")` force-emits 100 `row-start-*` utilities into all 4 consuming apps' bundles; repo-wide, only `row-start-1` is used (statically — no `row-start-${…}` template usage found). ~3.5 KB unminified dead CSS per app. Trim the range or drop the line.                                                                                                                                                                                                                                                                                                                                                                                                    |
| PERF-3 | `backoffice.css:8`              | **Low.** `@source "../../apps/**/*.{ts,tsx}"` sweeps `apps/sso` (44 `.ts` files, an Express backend with zero Tailwind classes — its templates use hand-authored CSS) on every consuming app's build. Wasted scan I/O today; the surface silently grows with SSO. Note the broad glob **is** load-bearing for the CRM MFE remotes (they ship no CSS entry and rely on host scanning) — exclude sso rather than narrowing the glob naively.                                                                                                                                                                                                                                                          |

## Refuted in the 2026-07-03 hunt (recorded so nobody re-chases them)

- `@source inline("min-w-{xs..xl}")` invalid in v4 — refuted; v4 generates these from the `--container-*` scale and `min-w-xs`/`min-w-sm` are used in e2e/filters.
- Cross-app CSS contamination via the `apps/**` glob — the breadth is load-bearing for CRM MFE remotes (Module Federation, no own Tailwind build).
- Google Fonts `@import` risk, view-transition global override, `--color-secondary` conflict — all live only in dead `global.css`.
- Dynamic `grid-cols-${…}` broken by the disconnected safelist — the one dynamic site resolves to `grid-cols-4`, which appears statically in scanned sources; `grid-cols-7` is a static literal in scanned `ui` sources.
- Security sweep (remote URLs, credentials, known CVEs) — nothing applicable to CSS/config files.

## Suggested order

1. **Mechanical, zero-risk fixes**: BUG-4 (fix the `[ACTIVE]` labels + INTENT.md row), SMELL-1 (delete the duplicate Quill block), CONV-1 (`"private": true`), PERF-2 (trim `row-start` range).
2. **The sizing-system repair (one PR)**: BUG-1 (define/map `--font-size-*`), BUG-2 (rename the second selector to `.button-lg.rounded-full`), BUG-3 (lg line-height), BUG-6 (add `.icon-xs`), SMELL-5 (fix or delete `dropdown-image-md/lg`) — then eyeball the new-order wizard and the `control-md` atoms in Storybook.
3. **`@source` hygiene**: PERF-1 (add `services` + `file-uploader` entries — do this before either package ships a unique class), PERF-3 (exclude `apps/sso`).
4. **Behavioral changes needing an owner ruling**: BUG-5 (`width: 100vw` → `100%`; verify no layout depends on the overflow), SMELL-4 (`.border` augmentation: rename vs document), SMELL-3 (delete the four dead files — pending the Open-questions ruling in [[tailwind-config-intent]]).
